## 프로젝트 포트폴리오

### 1. 개요 (Overview)

- 프로젝트 이름: kant_project_1
- 기간: 09.14 ~ 09.18
- 팀 구성: 4명, 모델 리서치 / 실험 성능 측정 및 평가
- 한 줄 소개: 두 모델 중 목적에 가장 적합한 모델을 선택하기 위해 성능을 비교합니다. 
- 왜 이 프로젝트를 했는지: AI 모델이 빠르게 다양해지면서, 같은 작업에도 모델별 성능과 효율에 차이가 나타나고 있습니다. 이에 각 모델의 강점과 적합한 활용 목적을 비교 · 분석하여, 상황별로 가장 알맞는 모델을 선택할 수 있는 기준을 마련하고자 본 프로젝트를 진행했습니다. 
### 2. 기술 스택

- 언어/프레임워크 (백엔드, 프론트엔드)
- DB (MySQL/PostgreSQL 등)
- 배포/인프라 도구 (Docker, AWS, Nginx, GitHub Actions 등)
- 이유도 한 줄씩: "왜 이 기술을 선택했나" (없으면 없다고 솔직히 적어도 됨, 나중에 채우면 됨)

### 3. 아키텍처 (구조도)

- 지난번 그려드린 것 같은 다이어그램: 사용자 → 서버 → DB 흐름
- 배포 파이프라인 그림 (코드 push부터 서비스 반영까지)
- 그림 하나로 전체 시스템이 한눈에 보이게

### 4. DB 설계

- ERD (테이블 관계도)
- 왜 이렇게 테이블을 나눴는지, 주요 인덱스는 뭘 걸었는지
- 어려웠던 설계 결정 (예: 정규화 vs 비정규화 고민)

### 5. 핵심 기능 및 구현 포인트

- 가장 어려웠던 기능 2~3개를 골라서
    - 문제 상황 → 어떻게 접근했나 → 어떤 코드/설계로 풀었나
- 코드 스니펫 포함하면 좋음

### 6. 배포 및 인프라 과정

- 로컬에서 실제 서비스로 올라가기까지 과정
- CI/CD를 썼다면 파이프라인 단계 설명
- 트러블슈팅: 배포 중 겪은 에러와 해결법

### 7. 트러블슈팅 / 궁금했던 질문

- 이게 제일 중요한 섹션입니다. 면접관들이 제일 좋아하는 부분이에요.
- 형식: "문제 상황 → 원인 파악 과정 → 해결 방법 → 배운 점"
- 예: "왜 특정 API가 느렸나 → 쿼리 분석해보니 N+1 문제 → 인덱스 추가/쿼리 최적화로 해결"
- 지금 궁금한 게 없어도 나중에 하나씩 채워나가면 됩니다 (지난번 드린 질문 리스트가 이 섹션 채우는 데 쓰일 재료입니다)

### 8. 결과 및 회고

- 정량적 성과가 있다면 (응답속도, 처리량 등)
- 아쉬웠던 점, 다음에 개선하고 싶은 점
- 이 프로젝트로 배운 것 (기술적/협업적)

### 9. 실행 방법 (선택)

- 로컬에서 돌려볼 수 있게 설치/실행 가이드
- 채용담당자가 직접 돌려볼 수도 있으니 있으면 플러스
