## 1. 공정한 비교를 위해 "동일하게" 맞춰야 할 조건

하나라도 다르면 결과가 모델 성능 차이인지 조건 차이인지 구분이 안됩니다.

환경/실행 조건
- 같은 하드웨어(GPU/VRAM/CPU)에서 실행 - 다른 PC결과를 섞으면 안됨
- 같은 양자화 수준 비교인지 확인 - Q4_K_M vs Q4_O처럼 양자화가 다르면 모델 성능이 아니라 양자화 손실 차이를 보는 것일 수 있다.
- 같은 컨텍스트 길이 설정

입력/실행 파라미터
- temperature, top-p, top_k, seed 등 샘플링 파라미터 통일(특히 temperature=0으로 고정하면 재현성 확보에 유리)
- 같은 프롬프트 템플릿/시스템 프롬프트 구조 사용
- few-shot 예시를 쓴다면 개수, 내용을 동일하게
- 한 번만 실행하지 말고 반복 횟수(n회) 통일 - 지금 하신 것처럼 2회 반복은 최소치, 가능하면 3~5회 이상 권장

데이터/테스트셋
- 같은 테스트셋, 같은 순서로 실행
- 학습(파인튜닝) 여부가 다르면 반드시 명시(fine-turned vs base 모델을 섞어서 비교하면 안됨)
- 테스트셋이 특정 모델의 학습 데이터에 포함됐을 가능성(데이터 오염)체크

## 2. 모델 선징시 고려할 것

- 목적 부합성 :코딩 특화 모델 vs 범용 모델 - 태스크에 맞는 카테고리로 비교해야 의미가 있따.
- 파라미터 규모 유사성: 7B vs 6.7B 정도는 비슷한 체급이라 볼 수 있지만, 4B vs 8B처럼 체급이 크게 다르면 모델 설계 차이가 아니라 규모 차이를 보는 셈이다. 
- 양자화 수준: 같은 비트수로 맞추거나, 다르면 그 자체를 변수로 명시 
- 라이선스: 실무/상업적 사용 가능 여부
- 컨텍스트 윈도우 길이: 긴 문서 처리가 필요한 태스크면 지원 컨텍스트 길이 차이에도 성능에 영향
- 최신성/ 커뮤니티 지원: 업데이트 주기, 버그 픽스, 커뮤니티 벤치마크 존재 여부 
- 멀티링구얼 지원 수준: 한국어 태스크라면 한국어 학습 데이터 비중이 명시돼 있는지 확인

## 3. 결과 지표에서 비교해야 할 것

#### 정확도/품질 지표(태스크별로 다름)

- 분류 태스크(KLUE-TC/YNAT): Accuracy, F1(macro/micro), 클래스별 Recall·Precision, 혼동행렬
- 코딩 태스크: 테스트 통과율, 완전 해결 비율, 재현성
- 실패 유형 분류: 단순 오답, 형식 오류, 타임 아웃, 호출 실패 - 이걸 구분해야 왜 실패했는지 알수 있다.

#### 속도/효율 지표

- 평균 응답 시간(첫 토큰까지 걸리는 시간 TTFT도 있으면 좋다)
- 토큰 생성 속도(tokens/s)
- 워밍업/콜드 로딩 시간과 웜 상태 시간을 구분해서 표기 

#### 리소스 사용량

- VRAM 사용량
- RAM/CPU 사용량
- 배터리/전력 소비

#### 일관성/신뢰도 지표
- 같은 입력에 대한 반복 실행 시 결과 편차 (분산, 표준편차)
- 통계적 유의성: 샘플 수가 적으면 "통계적 우위" 라고 단정하지말고 "탐색적 결과"로 표현 

## 4. 더 깊게 고려하면 좋은 것들

- 테스트셋 대표성: 몇 개 문제로 전체 개발 능력/언어 능력을 일반화할 수 없음. 카테고리별 난이도, 주제 다양성을 의도적으로 설계했는지 확인
- 벤치마크 오버피팅 가능성: 모델이 유명 벤치마크 데이터로 학습됐을 가능성
- 비용 관점: 토큰당 비용, 로컬 실행이면 전기/시간 비용도 실무 판단에 포함
- 실사용 시나리오와의 격차: 벤치마크 점수가 높아도 실제 사용 환경(긴 대화, 실제 사용자 입력)에서는 다르게 동작할 수 있다.
- 안전성/편향: 특정 카테고리에서 편향된 답변을 하는지 (분류 태스크라면 특정 클래스에 치우친 오분류가 있는지)
- 평가자 신뢰도: 코딩 테스트처럼 자동 채점이 가능한 경우가 아니라면, 사람이 평가할 때 평가자 간 일치도(inter-rater-agreement)도 고려

# 요약 체크리스트(실행 전 최종 확인)

- 같은 하드웨어/프레임워크/버전인가
- 같은 양자화 수준인가 (다르면 명시했는가)
- 같은 포롬프트 템플릿·파라미터(temperature 등)인가
- 체급(파라미터 수)이 비슷한 모델을 비교하는가
- 정확도 + 속도 + 리소스 + 일관성 지표를 모두 기록했는가
- 실패를 유형별로 분류했는가
- 샘플 수 대비 과도한 결론을 내리지 않았는가
- 결과가 특정 개인 PC 환경에 국한된 것인지 명시했는가
